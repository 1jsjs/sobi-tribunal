## 1. 4축 정의 (소비 MBTI — 출처: MPiA 블로그, blog.naver.com/ezpbill/224270065491)

| 축 | 질문 주제 | 앞 글자 | 뒤 글자 |
|---|---|---|---|
| **E / G** | 돈 관리 방식 | E 관리·절약·통제 (기록하고 지출 규모를 정확히 앎) | G 자유·여유·유연 (연연하지 않고 필요할 때 통 크게) |
| **R / I** | 소비 패턴의 일정함 | R 매달 비슷하게 쓰고 저축 | I 즉흥적, 많이 쓰는 달이 있음 |
| **F / S** | 소비의 목적 | F 실용·기능 중심 | S 스타일·패션·쇼핑 중심 |
| **Q / D** | 소비의 무대 | Q 집·차분·조용 | D 만남·바깥·활동 |

주: F/S·Q/D의 공식 문구 이미지는 팀 노션에 아직 없음("이미지 추가" 상태).
위 정의는 16유형 표에서 역산한 것 — 팀이 블로그 원문 확인 후 어긋나면 이 표만 고친다.

## 3. 질문 뱅크 (기본 문구 — LLM이 물건 맞춤으로 재작성하되 구조·태그는 불변)

pole 표기: 축 점수 기여. 답변 pole = **±2**, 조서 선반영 = **±1** (답변이 항상 이긴다).
guilt = 유죄 점수 기여.

| id | axis | askIf | 기본 문구 | 선택지 (pole / guilt) |
|---|---|---|---|---|
| USE | GUILT | 항상 | 지금 그 물건은 어디서 무엇을 하고 있소? | ① 거의 매일 쓰고 있습니다 (—/0) ② 가끔… 생각나면 씁니다 (—/1) ③ …아직 포장도 안 뜯었습니다 (—/3) |
| EG1 | EG | 항상 | 이걸 결제하던 순간, 이번 달에 얼마나 썼는지 알고는 있었소? | ① 네, 가계부에 다 적혀 있습니다 (E/0) ② 대충 감으로는 알고 있었습니다 (—/1) ③ 통장 잔고는 보는 게 아니라고 배웠습니다 (G/2) |
| RI1 | RI | 항상 | 이런 종류의 소비, 이번이 처음이오? | ① 매달 정해둔 만큼만 삽니다 (R/0) ② 처음은 아니지만 드문 일입니다 (—/0) ③ …서랍에 비슷한 게 몇 개 더 있습니다 (I/2) |
| FS1 | FS | 항상 | 그 물건, 쓰려고 샀소 — 아니면 예뻐서 샀소? | ① 필요해서 샀습니다. 기능을 보고 골랐습니다 (F/0) ② 예쁘면 그게 곧 필요한 것 아니겠습니까 (S/1) |
| QD1 | QD | 항상 | 그 물건은 주로 어디에서 활약하는 물건이오? | ① 집입니다. 제 방에서 씁니다 (Q/0) ② 밖입니다. 사람들 만날 때 빛을 봅니다 (D/0) |
| EG2 | EG | EG점수==0 | 그래서, 가격 비교는 해보고 산 것이오? | ① 세 군데는 비교하고 최저가로 샀습니다 (E/0) ② 첫눈에 반해 그 자리에서 결제했습니다 (G/2) |
| RI2 | RI | RI점수==0 | 피고인의 지출은 매달 비슷하오, 들쭉날쭉하오? | ① 매달 거의 똑같습니다 (R/0) ② 꽂히는 달엔 크게 나갑니다 (I/1) |
| RETURN | GUILT | 항상 | 마지막으로 묻겠소. 그날로 돌아간다면, 또 사겠소? | ① 네. 백 번이라도 다시 삽니다 (—/0) ② …조금 더 고민은 해볼 것 같습니다 (—/1) ③ 안 삽니다. 그 돈이면… (—/2) |

- 진행 순서 고정: USE → EG1 → RI1 → FS1 → QD1 → (EG2) → (RI2) → RETURN. 총 6~8문.
- LLM 재작성 규칙: 문구(text·choices label)만 바꾼다. 질문 수·선택지 수·순서·태그 변경 금지.
  재작성 결과 검증 실패(개수 불일치 등) 시 그 질문은 기본 문구로 폴백.

## 4. 축 판정 룰

1. 조서 선반영(±1): `FASHION_BEAUTY → S`, `LIVING_GROCERY → F`, `HOBBY_LEISURE → D`. 그 외 0.
2. 답변 합산(±2): 각 답변 pole을 해당 축에 더한다.
3. 축별 최종: 합 > 0 → 앞 글자(E/R/F/Q), 합 < 0 → 뒤 글자(G/I/S/D),
   **합 == 0 → 앞 글자** ("의심스러울 때는 절제의 이익으로" — in dubio pro reo).
   (부호 규약: 앞 글자 = +, 뒤 글자 = −)
4. axisCode = 4글자 연결 → §2 표에서 typeName/typeEmoji.

## 5. 유죄 점수 룰

1. 답변 guilt 합산 (§3 표).
2. 서버 보정: USE 답이 ③(포장 안 뜯음)이고 price ≥ 100,000 → **+1**.
3. 등급: **0~3 무죄(INNOCENT) / 4~6 집행유예(PROBATION) / 7+ 유죄(GUILTY)**.
4. costPerUse(회당 단가): USE ①→null, ②→round(price/3), ③→price(사용 0회, 전액).

### 형량(sentence) — 최다 기여 요인 기준 템플릿 (LLM 아님)
| 최다 기여 | 형량 |
|---|---|
| USE(안 씀) | "피고인은 7일 이내 위 물건을 1회 이상 사용하거나, 중고 장터에 등록할 것을 명한다." |
| EG(즉시 결제·잔고 무지) | "피고인은 다음 5만원 이상 결제 전 24시간의 숙려 기간을 가질 것을 명한다." |
| RI(서랍에 또 있음) | "피고인은 보유 중인 동종 물품의 전수 조사를 실시하고 그 목록을 제출할 것을 명한다." |
| RETURN(후회 자백) | "피고인은 환불·교환 가능 여부를 24시간 이내 확인할 것을 명한다." |
| 무죄일 때 | "본 법정은 위 소비를 훌륭한 소비로 인정한다. 피고인은 당당히 사용할 것." |
동점이면 표의 위쪽이 우선.

## 6. 심증 게이지 (프론트 표시 전용 — 판정과 무관)
- 확정 축 수(합≠0인 축) 기준: 0개 15% → 1개 35% → 2개 55% → 3개 75% → 4개 95%.
- 확정 축 2개부터 "유력 용의 유형" 이름을 노출(미확정 축은 기본 글자로 채워 조회).
- 게이지 문구: "심증이 굳어가고 있소…" → 4축 확정 시 "판사의 심증이 섰소."
