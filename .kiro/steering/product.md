# 소비 재판소 — 제품 정의 (v3, 8/28 전면 재시작판)

## 한 줄
"이거… 내가 왜 샀지?" 싶은 소비 **한 건**을 사진으로 기소하면, AI 판사가
아키네이터처럼 6~8개 질문으로 심문하고 **유·무죄 판결 + 소비 유형(16종)**을 선고하는 웹 앱.

## 핵심 전환 (이전 버전과 다른 점)
- 월 가계부 전체 분석이 **아니다**. 후회 소비 **1건**이 재판 1건이다.
- 입력은 타이핑이 아니라 **사진 1장**: 결제내역 캡처 / 영수증 / 제품 사진(가격 포함).
- 판정 유형은 7종 룰이 아니라 **소비 MBTI 16유형**(4축 × 2, 출처: MPiA 블로그 — 화면에 출처 표기).

## 사용자 흐름 (화면 6개)
1. **소환장** — 이메일 입력 = 피고인 출석 확인(비밀번호 없음, localStorage 기억)
2. **기소** — 사진 업로드(또는 수동 입력 폴백). 캡처에 거래가 여러 건이면 한 건 선택
3. **조서 확인** — 비전이 뽑은 품목/가격/날짜를 수정 가능한 카드로 확인 ("이 물건이 맞소?")
4. **법정(심문)** — 판사가 질문 6~8개를 하나씩. 답은 선택지 탭. 화면 한쪽에 업로드한
   사진이 "증거물 제1호" 액자로 걸려 있고, 답할 때마다 심증 게이지가 차오른다
5. **판결** — 도장(유죄/집행유예/무죄) 쾅 → 판결문 낭독 → 소비 유형 카드 + 형량(미션)
6. **전과 기록** — 내 이메일로 판결받은 소비들의 목록(회고 아카이브)

## 재판의 규칙 (절대 원칙)
- **판정은 룰, 문장은 LLM.** 축 점수·유죄 점수·유형 확정은 전부 서버의 결정적 룰이다.
  LLM(Bedrock)은 ①사진→조서 추출 ②질문 문구를 그 물건에 맞게 재작성 ③판결문 산문 생성만 한다.
- LLM이 전부 실패해도 기본 질문 뱅크와 템플릿 판결문으로 **재판은 끝까지 진행된다.**
- 가끔 **무죄가 나와야 한다.** 앱이 잔소리꾼이 되면 재미가 죽는다.
  (동점 판정 기본값도 "의심스러울 때는 절제의 이익으로" = E/R/F/Q 쪽.)

## 말투
판사는 근엄한 옛말투("~하시오", "~인 것이오")에 MZ 밈을 한 방울 섞는다.
정색한 문어체 틀 안에서 내용이 웃긴 것이지, 판사가 이모티콘을 쓰지는 않는다.
